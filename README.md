# Танковый бой

Браузерная многопользовательская игра про танки. Одна комната, вход по имени,
3D на three.js, авторитетный сервер на Node + WebSocket.

Сейчас реализовано: заезд в комнату, катание по карте с препятствиями,
столкновения, стрельба с уроном и респавном, ники и полоски здоровья над танками.

## Управление

| Действие | Клавиатура | Телефон |
| --- | --- | --- |
| Вперёд / назад | `W` / `S` | левая половина экрана — джойстик |
| Поворот корпуса | `A` / `D` | тот же джойстик |
| Башня и камера | мышь (клик по экрану — захват курсора) | правая половина экрана — свайп |
| Огонь | ЛКМ или `Пробел` (удержание стреляет очередью по мере перезарядки) | кнопка «Огонь» |
| Отпустить курсор | `Esc` | — |

## Бой

100 HP, снаряд снимает 25 — четыре попадания на танк. Перезарядка 1.6 с,
после уничтожения танк возвращается через 4 с на свободной точке спавна.

Снаряд летит по прямой на 62 м/с, без гравитации: карту в поперечнике проходит
за 2.3 с, так что по едущей цели нужно упреждение. Летит он на высоте 2.15 м —
ниже любого блока на карте, поэтому за укрытием можно спрятаться.

## Запуск для разработки

```bash
npm install
npm run dev
```

`npm run dev` поднимает игровой сервер на `:8080` и vite на `:5173`.
Открывать нужно `http://localhost:5173` — vite сам проксирует `/ws` на сервер.
Чтобы проверить мультиплеер, открой вторую вкладку с другим именем.

Полезные команды:

```bash
npm run typecheck        # проверка типов
npm run check:map        # спавны не должны попадать внутрь препятствий
npm run check:smoothness # рывки предсказания в числах, сервер не нужен
npm run check:combat     # урон, перезарядка, укрытия, респавн — на живом классе Room
npm run smoke            # два бота заходят, едут и стреляют; сервер должен быть запущен
npm run build       # клиент в dist/
npm run build:server # сервер в dist-server/
```

## Архитектура

```
src/shared/   логика, общая для клиента и сервера
  sim.ts        stepTank() — вся физика танка, один шаг
  constants.ts  тик, скорости, размеры карты
  map.ts        препятствия и точки спавна
  protocol.ts   типы сообщений WebSocket
src/server/   авторитетный сервер: тик 30 Гц, снапшоты всем
src/client/   three.js и интерфейс
  prediction.ts предсказание, реконсиляция, сглаживание — без DOM, поэтому тестируется
```

Ключевая идея: **движение описано ровно один раз** — в `stepTank()`.
Сервер крутит её как источник истины, клиент крутит ту же функцию,
чтобы предсказывать свой танк локально и не ждать ответа сервера.

Как это работает по шагам:

1. Клиент 30 раз в секунду шлёт **инпут** (`газ`, `руль`, `угол башни`) с номером `seq`.
   Координаты клиент не присылает никогда — иначе телепорт-читы были бы бесплатны.
2. Сервер тикает 30 Гц, применяет инпуты и рассылает снапшот со своим `ack` —
   номером последнего применённого инпута каждого игрока.
3. Клиент, получив снапшот, ставит свой танк в серверную позицию и **переигрывает**
   все инпуты новее `ack`. Расхождение гасится плавно за пару кадров, без рывка.
4. Чужие танки рисуются с задержкой 100 мс и интерполяцией между снапшотами —
   так они едут плавно, а не телепортируются 30 раз в секунду.

Снаряды клиент не предсказывает: они рождаются и летят только на сервере, а
клиент рисует их из снапшотов той же интерполяцией и с той же задержкой, что и
чужие танки. Иначе снаряд и цель жили бы в разных моментах времени и попадания
не сходились бы с картинкой. Взрывы тоже придерживаются на 100 мс — вспышка
должна совпасть с тем кадром, где снаряд дошёл до места.

Компенсации лагов («попадание в прошлом») нет и пока не нужно: снаряд летит
2 с через карту, поэтому упреждение всё равно берёт игрок, а не сервер.

Два правила, которые легко нарушить и получить дрожащую картинку:

- **Кадр рисуется между шагами симуляции.** Шаг идёт 30 раз в секунду, экран —
  60–144, поэтому позиция всегда интерполируется по остатку аккумулятора.
- **Поправка сервера не двигает картинку.** Траектория сдвигается на поправку,
  а такой же противоход кладётся в `error` и гаснет за ~100 мс. Считать расхождение
  надо между чистыми состояниями симуляции: если взять нарисованную позицию,
  в него попадёт намеренное отставание кадра и сложится само с собой.

`npm run check:smoothness` меряет оба правила численно и сравнивает с реализацией
до исправления.

## Деплой (Ubuntu + Docker)

Два контейнера: `server` (игровой цикл) и `web` (nginx: статика + прокси `/ws`).

```bash
git clone <репозиторий> && cd tanks_battle
docker compose up -d --build
```

После этого игра доступна на `http://<домен>`. Проверить живость: `curl http://<домен>/health`.

Ресурсы поделены в `docker-compose.yml`: серверу 1 ядро и 1 ГБ, nginx — половина
ядра и 256 МБ. Игровой цикл однопоточный, так что второе ядро ему не нужно.

### Что должно быть на сервере

- **Docker Engine 20.10+ с плагином `compose` v2** (`docker compose`, не старый
  `docker-compose`). Больше ничего ставить не нужно: Node, npm и nginx живут
  внутри образов, на хосте их нет.
- **git** — воркфлоу поставит сам, если не найдёт.
- Пользователь деплоя должен уметь `sudo docker ...` без пароля (или лежать
  в группе `docker`, тогда `sudo` перед docker в воркфлоу можно убрать).
- Свободные ~1.5 ГБ RAM на время сборки: образы собираются на самом сервере
  (`npm ci` + vite). На 4 ГБ VPS это проходит спокойно.
- ~2 ГБ диска под образы. Воркфлоу после деплоя делает `docker image prune -f`,
  так что старые слои не копятся.

### Порты

| Порт | Куда | Зачем |
| --- | --- | --- |
| 22 (или свой) | извне | SSH для деплоя |
| 80 | извне | игра и WebSocket `/ws` |
| 443 | извне | то же самое по TLS, см. ниже |
| 8080 | **только внутри** docker-сети | игровой сервер; наружу не публикуется |

В `docker-compose.yml` у сервиса `server` стоит `expose`, а не `ports`, — до
игрового сервера можно достучаться только через nginx. Открывать 8080 в фаерволе
не нужно и не следует.

### Автодеплой через GitHub Actions

Файл [.github/workflows/deploy.yml](.github/workflows/deploy.yml). Срабатывает на
push в `main` и по кнопке (`workflow_dispatch`). Два джоба:

1. **checks** — `typecheck`, `check:map`, `check:combat`, `check:smoothness` и обе
   сборки. Сломанный коммит до сервера не доезжает.
2. **deploy** — заходит по SSH, обновляет `/srv/tanks_battle` до `origin/main`,
   поднимает `docker compose up -d --build` и дожидается ответа от `/health`.

`down` перед `up` не делается: compose пересоздаёт только изменившиеся контейнеры,
поэтому простой — секунды, а не всё время сборки образа.

Секреты репозитория (Settings → Secrets and variables → Actions):

| Секрет | Что это |
| --- | --- |
| `SSH_HOST` | IP или домен VPS |
| `SSH_USER` | пользователь на VPS |
| `SSH_PORT` | порт SSH; можно не задавать, тогда 22 |
| `SSH_KEY` | приватный ключ, которым Actions заходит на VPS |
| `GIT_DEPLOY_KEY` | приватный ключ, которым **VPS** тянет репозиторий с GitHub |

Ключей два, потому что это два разных перехода: раннер → сервер и сервер → GitHub.

```bash
# 1. Ключ раннера. Публичную половину — в ~/.ssh/authorized_keys на VPS.
ssh-keygen -t ed25519 -f runner_key -N '' -C 'github-actions'

# 2. Deploy key репозитория. Публичную половину — в Settings → Deploy keys
#    (доступ на чтение достаточен), приватную — в секрет GIT_DEPLOY_KEY.
ssh-keygen -t ed25519 -f deploy_key -N '' -C 'tanks_battle deploy'
```

Приватные ключи копируются в секреты целиком, вместе со строками
`-----BEGIN OPENSSH PRIVATE KEY-----` и `-----END ...-----`.

Первый запуск сам склонирует репозиторий в `/srv/tanks_battle`, каталог заранее
готовить не нужно.

### HTTPS

Браузер разрешает `wss://` только с валидным сертификатом, поэтому для боевого
домена нужен TLS:

```bash
sudo certbot certonly --standalone -d tanks.example.com
```

Затем в `docker/nginx-tls.conf` подставить свой домен, а в `docker-compose.yml`
раскомментировать порт `443` и оба монтирования, после чего:

```bash
docker compose up -d --build web
```

Клиент сам выберет `ws://` или `wss://` по протоколу страницы — менять код не нужно.

Правки `docker-compose.yml` под TLS нужно **закоммитить в репозиторий**, а не
править на сервере: деплой делает `git reset --hard origin/main` и стирает всё,
что отличается от коммита. Сертификаты в `/etc/letsencrypt` это не трогает.
